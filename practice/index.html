Quản lý sản phẩm VIC

Mỗi người tự hoàn thành cả backend Node.js và frontend gọi backend. Mọi bài dùng chung products nên thay đổi của thành viên khác sẽ thấy khi tải lại.

Supabase thật · dùng chung CLBKhông chia dữ liệu theo slug
Cẩn thận khi thử nghiệm: POST/PATCH/DELETE sau khi bạn tự hoàn thành API sẽ thay đổi dữ liệu thật mà cả CLB đang dùng. Không chạy seed/reset và không gửi dữ liệu thử nghiệm nhạy cảm. Tải lại trang sẽ gọi GET từ backend để xem trạng thái mới nhất.
Mục tiêu

Một bảng, đủ luồng CRUD

Yêu cầu chính: GET danh sách, POST, PATCH và DELETE. Frontend gửi dữ liệu đến API riêng trong thư mục bài của bạn. Backend kiểm tra dữ liệu rồi thao tác bảng public.products qua Supabase.

Luồng bắt buộc
Browser → API Node.js do bạn viết → Supabase → response → giao diện. Không gọi Supabase trực tiếp từ browser; không dùng mảng hoặc localStorage làm nguồn sự thật.
Hợp đồng API

Endpoint cần hoàn thành

Các endpoint dưới đây là yêu cầu chính trong bài 60 phút.

MethodPathYêu cầuThành công
GET/api/productsĐọc danh sách chung200 · mảng JSON
POST/api/productsBody: name, price, stock201 · sản phẩm mới
PATCH/api/products/:idSửa một hoặc nhiều trường200 · sản phẩm sau sửa
DELETE/api/products/:idXóa đúng id204 · không có body

Lỗi dùng JSON nhất quán, ví dụ {"error":{"code":"VALIDATION_ERROR","message":"Thông tin không hợp lệ"}}. Dùng 400 cho input sai, 404 khi không có id, 500 cho lỗi server. Backend vẫn phải validate dù form có kiểm tra cơ bản.

Bài mở rộng sau khi yêu cầu chính chạy

Thêm GET /api/products/:id, PUT yêu cầu đầy đủ trường, và tìm kiếm ?q=. Query tìm kiếm phải do backend chuyển thành điều kiện truy vấn, không tải toàn bảng về rồi lọc ở frontend.

Categories đã có sẵn để làm dữ liệu tham chiếu. Bài nhập môn không làm CRUD danh mục; backend đọc LAB_CATEGORY_ID từ cấu hình chung và tự gán khi tạo. Response API dùng categoryId; tên cột database nội bộ vẫn là category_id.

Kế hoạch 60 phút

Làm theo từng chặng

  1. 0–8 phút · Chạy projectTạo branch feature, chạy server, mở bài trong codeapi/<slug>/. Agent được phép hỗ trợ nhưng hãy nêu rõ phần bạn chưa hiểu.
  2. 8–18 phút · GETTự viết hàm fetch GET; khi mở trang hãy tải dữ liệu và render loading, rỗng, lỗi cùng bảng sản phẩm.
  3. 18–32 phút · POSTViết route POST và hàm fetch tạo sản phẩm; validate ở backend, gán category_id từ config. Sau response 201, gọi GET lại.
  4. 32–45 phút · PATCHViết route PATCH và hàm fetch sửa một hoặc nhiều trường. Khi submit, phân biệt tạo/sửa theo trạng thái form. Sau response 200, gọi GET lại.
  5. 45–53 phút · DELETERender bảng từ response API, xác nhận trước khi xóa; trả 204 không body. Sau đó GET lại và báo lỗi nếu người khác đã xóa trước.
  6. 53–60 phút · Git và reviewHoàn thiện trạng thái loading/lỗi, chạy kiểm tra cơ bản, commit rõ, push branch, mở PR. Giải thích một request và một quyết định trong code.
Làm cùng Agent

Giao việc nhỏ, kiểm tra lại

  • Yêu cầu Agent giải thích API contract trước khi sửa code.
  • Chỉ định rõ file bạn đang làm trong thư mục cá nhân; không sửa router hoặc bài của người khác.
  • Nhờ hoàn thành một endpoint, đọc diff, tự chạy request và yêu cầu Agent giải thích status/error.
  • Không đưa key, mật khẩu hoặc file cấu hình vào prompt, log hay ảnh chụp.
  • Mỗi người vẫn phải tự viết backend và phần frontend gọi backend; scaffold có TODO, không có lời giải hoàn chỉnh.
Chuẩn bị

Chạy app chung

  1. Node.js 22 trở lên
  2. npm ci
  3. npm run member -- ten-cua-ban
  4. npm start

Lệnh tạo bài chỉ tạo folder/template. Nếu server đang chạy, hãy restart để mount backend và đưa bài vào gallery. Không cần điền env; cấu hình lab đã được mã hóa trong repo.

Git flow

Nhánh ngắn, PR rõ

git switch -c feature/<slug>-products
# code + kiểm tra
git add codeapi/<slug>
git commit -m "feat: add products CRUD"
git push -u origin HEAD

Mở Pull Request về main, mời một bạn review. Không commit cấu hình riêng hoặc sửa bài của bạn khác.
